# Cloudflare request and D1 reductions
Production uses worker-api.mjs and public/ from the build. Static Assets serves matching files without Worker execution. HTML references fingerprinted JS/CSS under /static/ with one-year immutable caching; legacy URLs remain revalidatable for dynamic references and older clients. Cloudflare generates ETags. /api/* and /health execute the Worker. The existing worker.mjs bundle remains a compatibility/test artifact and is not the production entry point.
Polling serializes requests, backs off 10 -> 20 -> 40 -> 80 -> 120 seconds on unchanged revisions or failures, skips hidden/offline tabs and resets on received updates. Focus/visibility/manual checks remain available. Local writes retain the existing short debounce and conflict handling.
Note reminders are projected into note_reminder_schedule by workspace insert/update/delete triggers. This happens transactionally with the workspace CAS write. Cron reads indexed due rows, queues at most 100 per run, then validates pending sends against the current projection. Ordinary cron preparation reads workspaces only for accounts with a daily/weekly schedule matching the current hour. Job retries retain existing leases and idempotency keys. Cleanup runs in the first five minutes of each hour.
Apply server/migration-reminder-schedule.sql before deploying to an existing database; this backfills schedules. Fresh databases use schema.sql.
Public asset output is regenerated and ignored by git; run npm run build before deploy. No account-wide budget guarantee is implied; monitor actual usage, especially multiple active tabs and notification volume.
